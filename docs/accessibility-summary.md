# 无障碍检查摘要

- 生成日期：2026-11-16
- 检查对象：界面配色对比度检查器（`index.html`）
- 依据标准：WCAG 2.1 AA（SC 1.4.3 文本对比度、SC 1.4.11 非文本对比度、SC 2.4.7 焦点可见、SC 2.4.3 焦点顺序、SC 4.1.2 名称/角色/值）
- 计算方式：本地实现相对亮度与对比度公式，未调用任何外部检查库
- 自动化结果：内置用例 18/18 通过（100%），端到端用例 15/15 通过（100%），报告见 `artifacts/unit-report.json`、`artifacts/e2e-report.json`

## 一、对比度检查项与阈值

| 检查项 | 组合 | 最低要求 |
| --- | --- | --- |
| 正文文本 | `bodyText` / `pageBg` | 4.5:1 |
| 大号文本 | `largeText` / `pageBg` | 3:1 |
| 按钮文字 | `btnText` / `btnBg` | 4.5:1 |
| 非文本组件（按钮描边） | `btnBorder` / `pageBg` | 3:1 |
| 焦点指示器 | `focusRing` / `pageBg` | 3:1 |

不达标组合在结果表中以 `row-fail` 红底与“不达标”字样标记，Canvas 预览同步显示红色角标与实测比值。

## 三、已验证的操作路径

1. 鼠标：点击“错误场景”按钮，场景切换、`aria-pressed` 与结果表同步更新（E02、T09）。
2. 键盘 Tab：从导出按钮按 Tab，焦点移动到“运行全部测试”按钮，焦点 id 写入持久化状态（E05、T11）。
3. 键盘文本输入：在十六进制输入框键入合法色值即时重算；键入过程中非法中间态保留在输入框并显示字段错误（不打断逐字输入），失焦/回车提交时回滚到上一个有效值并经 `aria-live=assertive` 播报；按 Esc 随时还原（E04、T08、T17）。
4. 触屏：CDP 触摸事件（touchStart/touchEnd）点击边界场景按钮，到达与鼠标完全相同的功能状态（E06、T10）。
5. 错误恢复：错误场景点击“一键修复”，前景色迭代推向黑/白直到达标，5 项全部通过并播报修复的颜色键（E03、T06）。
6. 导出 CSS：生成含 `:root` 与 `--color-*` 变量的文件并写入 IndexedDB，导出前后当前色板字节级不变（E07、T13）。
7. 导出 PNG：Canvas 生成“调整前基线 / 调整后当前”双栏对比图（data URL，>48KB），附前后达标计数（E08、T14）。
8. 导出摘要：文本摘要包含“已验证的操作路径”与“失败恢复”章节并持久化（E09、T15）。
9. 刷新恢复：`Page.reload` 后场景、色板、`lastFocus`、导出记录数量与记录列表全部恢复（E10、T16）。
10. 重新载入：关闭页面后以同一用户目录重新打开，用户选择与已导出工程未被重置（E11）。
11. 读屏信息：结果摘要、polite/assertive 两个 live 区域随操作更新；结果表含 `caption`、6 个带 `scope=col` 的表头（E15、T12）。
12. Canvas 重绘：切换色板后画布非空像素 >5000，且 `role=img` 与中文 `aria-label` 保持可读（E14、T18）。

## 四、失败恢复机制

- 非法颜色：输入阶段仅标记错误不写入状态，提交（失焦/回车）时回滚到上一个有效值；Esc 可显式取消编辑。
- 对比度不达标：结果表与 Canvas 双重标记；“一键修复”自动收敛到达标色板，修复过程可重复、可验证。
- 持久化损坏：`localStorage` JSON 解析异常时回退到默认状态，不产生白屏。
- 导出安全：导出动作只读取当前状态，代码在导出前后比对色板快照，若被改动会通过 assertive 区域报错并中止。
- 刷新/重载：状态键 `contrast-checker-state-v1`（localStorage）与 IndexedDB 库 `contrast-checker-db` 共同保证选择、基线、焦点与导出工程不被悄悄重置。

## 五、残留风险与人工复核建议

- 自动化在 1280×900 桌面视口与模拟触摸下完成；真机移动端建议再做一次屏幕阅读器（NVDA/VoiceOver）走查。
- 对比度仅评估取色器中 8 个颜色键的指定组合；新增组件时需在 `js/palettes.js` 的 `CHECKS` 中补充检查项。
